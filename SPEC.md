# Спецификация: голосовой ввод требований к вакансии

Версия 0.1 (прототип). Документ описывает поведение так, чтобы по нему можно было сделать без вопросов. Тексты интерфейса лежат в `texts.js`, пороги в `config.js`, и в этом документе они не дублируются там, где достаточно ссылки.

## 1. Задача

Бизнес-заказчик отвечает голосом на 4 заранее заданных вопроса о будущем сотруднике. Система превращает речь в текст и собирает из ответов описание вакансии. Прогресс показывает кольцо из 4 сегментов (референс: Face ID). Сложность обработки скрыта: пользователь видит вопрос, кольцо, свой текст и кнопку.

Результат сценария: описание вакансии, которое можно скопировать. Публикации нет.

## 2. Допущения и решения

| Решение | Почему |
|---|---|
| Вакансия вместо резюме | В описании задания генерируется вакансия, слово «резюме» в критериях готовности считаем опиской. |
| «Он» в вопросах = будущий сотрудник | Заказчик описывает ещё не нанятого человека, поэтому вопросы в будущем времени. |
| Пропуск пункта 4 в исходном задании не влияет на реализацию | Нумерация пропускает пункт, содержания не теряет. |
| Mobile-first, одна колонка, контейнер до 480 px, отдельного десктопа нет | Сценарий линейный и голосовой, большая площадь ничего не даёт. На широком экране контейнер центрируется. |
| Текстовый ввод есть наравне с голосовым | Запасной путь при запрете микрофона, в браузере без распознавания и в шумном месте. |
| Итог на одном экране | Короче путь: описание и ответы рядом. |
| Правка транскрипта руками не делается, но заложена | См. раздел 5 и 14. |
| Анимация только у кольца на экранах вопросов и итога | Плавная заливка сегментов по часовой стрелке (референс: Face ID), подробности в разделе 9. Остальные элементы без переходов. |
| На стартовом экране и экране доступа к микрофону кольца нет, только крупная иконка | Кольцо там ничего не показывает: прогресс на этих экранах не нужен. |
| Кнопка «Назад» ведёт к предыдущему вопросу | Можно вернуться и перепроверить ответ, не доходя до итога. Подтверждённые ответы при этом не теряются. |
| Распознавание через Web Speech API | Работает в браузере без сервера. Ограничения в разделе 13. |
| Генерация описания шаблоном на правилах, с точкой замены на модель | Работает без сети и ключей. Уровень «max» по критериям закрыт частично, см. раздел 16. |

## 3. Что убрано

- Отдельная полоска прогресса: её заменяет кольцо.
- Кольцо на стартовом экране и экране доступа к микрофону.
- Настройки, выбор языка, история, аккаунт, шаринг, публикация: вне задачи.
- Отдельный десктопный лейаут: см. раздел 2.
- Кнопка «Закрыть» на экране итога и «Начать заново» с него: возврат к началу через перезагрузку, где черновик предложит «Начать заново».
- Реакция кольца на громкость голоса.

## 4. Экраны и переходы

Экраны: `welcome` (приветствие), `access` (доступ к микрофону, три вида: `prompt`, `denied`, `unsupported`), `question` (один компонент на вопросы 1–4), `summary` (итог).

| Откуда | Событие | Куда |
|---|---|---|
| welcome | «Начать» / «Продолжить» | Проверка микрофона: поддержки нет → access/unsupported; доступ запрещён → access/denied; доступ выдан → вопрос (первый без ответа, либо итог, если все 4 есть); иначе → access/prompt |
| welcome | «Начать заново» | Черновик очищается, далее как «Начать» |
| access/prompt | «Разрешить доступ» | Системный запрос; успех → вопрос; отказ → access/denied |
| access/denied | «Ввести текстом» | Вопрос в текстовом режиме, и следующие вопросы тоже открываются в текстовом режиме |
| access/denied | «Проверить снова» | Повторная проверка; выдан → вопрос; запрос не показан → access/prompt; закрыт → остаёмся и видим «Доступ всё ещё закрыт» |
| access/unsupported | «Ввести текстом» | Как выше |
| question | «Подтвердить» (после 600 мс на «Ответ принят») | Следующий вопрос; после вопроса 4 → summary |
| question (вопрос 2–4) | «Назад» | Предыдущий вопрос, его подтверждённый ответ открыт на проверке («Подтвердить» ведёт вперёд по цепочке к первому неотвеченному вопросу, а если все отвечены, на итог). Неподтверждённый ответ текущего вопроса отбрасывается |
| question (правка с итога) | «Назад» | summary без изменений и без пересборки описания |
| question | «Закрыть» | welcome; подтверждённые ответы сохранены, неподтверждённый текущий отбрасывается |
| summary | «Изменить» у карточки | question в режиме правки этого вопроса; после «Подтвердить» → summary, описание пересобирается |

## 5. Модель данных

Ответ на вопрос:

| Поле | Смысл |
|---|---|
| `raw` | Что услышала система. Не меняется после распознавания. |
| `text` | Что уходит в генерацию. Источник истины. |
| `source` | `voice` или `text`. |

Сейчас `text` равен `raw`, пока пользователь не перешёл на ввод текстом. Это и есть «заложено, не сделано» для правки транскрипта: когда её включат, она меняет только `text`.

Хранение: массив из 4 элементов (`null` или ответ) в `localStorage` по ключу из `DRAFT_KEY`. Пишется только в момент «Подтвердить». Аудио не хранится.

## 6. Параметры (`config.js`)

| Параметр | Значение | Смысл |
|---|---|---|
| `MIN_WORDS` | 4 | Минимум слов в ответе |
| `SILENCE_MS` | 6000 | Нет речи после старта записи → ошибка тишины |
| `LIMIT_MS` | 90000 | Жёсткий лимит записи |
| `WARN_BEFORE_LIMIT_MS` | 10000 | Предупреждение за N мс до лимита |
| `RECOGNITION_TIMEOUT_MS` | 5000 | Сколько ждём конца распознавания после остановки |
| `ACCEPT_DELAY_MS` | 600 | Пауза на «Ответ принят» |
| `GENERATION_DELAY_MS` | 900 | Имитация работы генерации |
| `GENERATION_SLOW_MS` | 10000 | Порог сообщения «Это занимает дольше обычного» |
| `COPIED_MS` | 2000 | Сколько кнопка показывает «Скопировано» |

Значения 4, 6 с и 90 с выбраны мной без данных исследования. Их стоит проверить на реальных ответах.

## 7. Состояния и критерии приёмки

Формат: «когда X, пользователь видит Y».

### Приветствие и доступ

| ID | Критерий |
|---|---|
| S0 | Когда открыт экран без черновика, пользователь видит крупную иконку микрофона без кольца, заголовок, «4 вопроса · около 3 минут» и кнопку «Начать». |
| S0-draft | Когда есть хотя бы один сохранённый ответ, пользователь видит иконку микрофона, «Отвечено N из 4», кнопку «Продолжить» и ссылку «Начать заново». Если ответов 4, заголовок «Все ответы собраны». |
| S1 | Когда доступ не выдан и нажато «Начать», пользователь видит объяснение, зачем нужен микрофон, и кнопку «Разрешить доступ». Системный запрос появляется только после её нажатия. |
| S1-denied | Когда доступ запрещён, пользователь видит причину, способ исправить, главную кнопку «Ввести текстом» и ссылку «Проверить снова». Сценарий не блокируется. |
| S1-unsupported | Когда браузер не поддерживает распознавание речи или страница открыта не по HTTPS, пользователь видит это и главную кнопку «Ввести текстом». |

### Вопрос (1–4)

| ID | Критерий |
|---|---|
| Q-ready | Когда открыт вопрос, пользователь видит счётчик «Вопрос N из 4», текст вопроса, подсказку, кольцо с активным сегментом, кнопку «Начать запись» и ссылку «Ввести текстом». Запись сама не стартует. |
| Q-recording | Когда нажато «Начать запись», пользователь не позже чем через 300 мс видит красный активный сегмент, таймер, поле живого транскрипта и кнопку «Остановить». |
| Q-recognizing | Когда запись остановлена, пользователь видит штриховой активный сегмент, уже распознанный текст на месте, строку «Распознаём…» и неактивную кнопку «Начать запись». |
| Q-review | Когда распознавание завершено, пользователь видит «Мы услышали:», транскрипт только для чтения, кнопку «Подтвердить» и ссылки «Записать заново» и «Ввести текстом». |
| Q-back | Когда на вопросе 2–4 нажата стрелка «Назад», пользователь видит предыдущий вопрос с его подтверждённым ответом на проверке, его сегмент остаётся залитым, а сегмент текущего вопроса плавно «разливается» в активный. На вопросе 1 кнопки нет. Во время «Ответ принят» кнопка неактивна. |
| Q-text | Когда выбран ввод текстом, пользователь видит поле ввода, подсказку «Минимум 4 слова» и кнопку «Подтвердить», неактивную, пока слов меньше минимума. Если есть ссылка «Записать голосом», она видна только пока голос доступен. |
| Q-accepted | Когда нажато «Подтвердить», пользователь видит, как сегмент плавно заливается цветом «выполнено» (`--dur`), галочку и «Ответ принят»; через `ACCEPT_DELAY_MS` открывается следующий вопрос, а после четвёртого итог. Ответ записан в черновик до начала паузы. |

### Ошибки

| ID | Критерий |
|---|---|
| E-silence | Когда речи нет `SILENCE_MS` после старта записи, пользователь видит остановленную запись, красный сегмент ошибки, сообщение «Не слышим голос…» и кнопки «Попробовать снова» и «Ввести текстом». |
| E-short | Когда ответ короче `MIN_WORDS`, пользователь видит транскрипт и сообщение «Ответ слишком короткий…», а «Подтвердить» неактивна. Выходы: «Записать заново» или «Ввести текстом» (поле предзаполнено услышанным, можно дописать). |
| E-recognition | Когда распознавание оборвалось с ошибкой, пользователь видит «Не удалось распознать запись…» и то, что успело распознаться. Кнопка «Продолжить запись» (или «Попробовать снова», если текста нет) дописывает к сохранённому. Ссылки «Записать заново» и «Ввести текстом». |
| E-interrupted | Когда приложение ушло в фон или экран заблокирован во время записи, при возврате пользователь видит «Запись остановилась…», записанную часть и кнопки «Продолжить запись» и, если текста достаточно, «Подтвердить как есть». |
| Rerecord | Когда нажато «Записать заново», пользователь видит чистое состояние Q-ready. Ранее принятый ответ этого вопроса остаётся в черновике, пока не подтверждён новый. В режиме правки об этом сказано в строке под кольцом. |
| Limit | Когда до лимита остаётся `WARN_BEFORE_LIMIT_MS`, пользователь видит «Осталось 10 секунд». На `LIMIT_MS` запись останавливается, ответ уходит в Q-review, и пользователь видит «Достигнут лимит записи — 90 секунд». |
| Close | Когда нажата «×» («Закрыть»), пользователь видит приветствие с «Продолжить», и все подтверждённые ответы сохранены. |

### Итог

| ID | Критерий |
|---|---|
| S2-generating | Когда подтверждён ответ 4, пользователь видит замкнутое кольцо, «Собираем описание вакансии…» и скелетон. Если дольше `GENERATION_SLOW_MS`, добавляется «Это занимает дольше обычного». Карточки ответов видны сразу, «Скопировать» неактивна. |
| S2-ready | Когда описание готово, пользователь видит текст вакансии по разделам, под ним 4 карточки ответов с «Изменить» и активную «Скопировать». |
| S2-error | Когда генерация не удалась, пользователь видит «Не удалось собрать описание. Ваши ответы сохранены.», 4 целых ответа и кнопку «Повторить». |
| S2-copied | Когда нажато «Скопировать», пользователь видит «Скопировано» на `COPIED_MS`, затем исходную подпись. Если копирование не удалось, подпись не меняется. |
| S2-edit | Когда нажато «Изменить», пользователь видит этот вопрос с пометкой «Изменить ответ», текущим ответом и строкой «Описание обновится.»; после «Подтвердить» возвращается на итог, где описание пересобирается. |

## 8. Чего делать нельзя

1. Терять ответ при любой ошибке, закрытии, сворачивании или обновлении страницы. Подтверждённые ответы живут в черновике. Распознанное, но не подтверждённое сохраняется в рамках текущего вопроса при ошибке и обрыве.
2. Переходить к следующему вопросу без нажатия «Подтвердить».
3. Запускать запись без явного нажатия «Начать запись» или «Продолжить запись».
4. Показывать системный запрос микрофона до нажатия «Разрешить доступ».
5. Блокировать сценарий при запрете микрофона: всегда есть ввод текстом.
6. Подтверждать ответ короче `MIN_WORDS`.
7. Перезаписывать принятый ответ до подтверждения нового.
8. Показывать сообщение об ошибке без указания, что делать.
9. Отправлять аудио или текст куда-либо кроме распознавания браузером. Генерация сейчас локальная.

## 9. Кольцо и анимация

Кольцо показано на экранах вопросов и итога. На стартовом экране и экране доступа к микрофону его нет, там крупная иконка (88 px) без обводки.

4 сегмента по 90° с зазором 16°, старт сверху, по часовой стрелке. Один сегмент на вопрос.

| Состояние сегмента | Вид |
|---|---|
| Пустой | Цвет трека |
| Активный (ready, text, первый просмотр) | Светлый акцентный |
| Активный при записи | Красный, мягко мигает; в центре иконка «волна» |
| Активный при распознавании | Акцентный штрих, «бегущие» штрихи по сегменту |
| Активный при ошибке | Цвет ошибки; иконка предупреждения |
| Выполненный | Акцентный сплошной. Также выполненным остаётся сегмент подтверждённого ответа, пока его просматривают через «Назад» |

Размеры: основной до 240 px (но не больше 30% высоты экрана), компактный 120 px в текстовом режиме, малый 96 px на итоге. Кольцо имеет `role="img"` и подпись «Заполнено N из 4».

### Анимация (референс: Apple Face ID)

| Событие | Что происходит | Длительность | Easing |
|---|---|---|---|
| Сегмент становится выполненным | Акцентная заливка набегает по сегменту по часовой стрелке от начала к концу | `--dur` = 550 мс | `cubic-bezier(0.4, 0, 0.2, 1)` |
| Выполненный сегмент перестаёт быть таковым (запись заново, возврат назад) | Заливка «убегает» обратно к началу сегмента | 550 мс | то же |
| Сегмент становится активным или пустым | Светлая подсветка появляется или гаснет | `--dur-fast` = 200 мс | то же |
| Идёт запись | Активный сегмент мягко мигает (непрозрачность 100% ↔ 45%) | 1400 мс, повтор | `ease-in-out` |
| Идёт распознавание | Штрихи на активном сегменте движутся по кругу | 1200 мс, повтор | `linear` |

Переход между состояниями кольца работает и при перерисовке экрана: кольцо рисуется с прошлым состоянием и затем переключается на новое, поэтому заливка именно «набегает», а не появляется. `ACCEPT_DELAY_MS` (600 мс) больше `--dur`, поэтому следующий вопрос открывается, когда заливка уже закончилась.

`prefers-reduced-motion: reduce`: все переходы и анимации выключены, сегмент меняет цвет мгновенно, мигание и бегущие штрихи отключены.

## 10. Тексты

Все строки в `texts.js`. Правила: обращение на «вы», короткие фразы, без восклицательных знаков, у каждой ошибки есть «что делать». Вопросы: сформулированы в будущем времени.

## 11. Доступность

- Все действия кнопки; зоны касания не менее 44×44 px, главная кнопка 52 px.
- Смена экрана переносит фокус на заголовок; смена состояния внутри вопроса озвучивается через `aria-live`.
- Счётчик «Вопрос N из 4» дублирует кольцо текстом.
- Контраст основного текста и кнопок не ниже 4.5:1 (заявлено по выбранным токенам, измерением не проверено).
- `prefers-reduced-motion: reduce`: переходы и анимации кольца отключены, состояния отличаются цветом и иконкой. Информация не опирается только на движение.
- Кнопка «Назад» имеет подпись для скринридера и зону касания 44×44 px.
- Размер шрифта поля ввода 16 px, чтобы iOS не увеличивал страницу.

## 12. Верстка

Сетка: одна колонка, контейнер до 480 px, отступы 20 px, нижняя зона закреплена и учитывает `safe-area`. Проверять на 390×844 и 360×640. Все цвета, размеры и радиусы вынесены в CSS-переменные в начале `styles.css`.

## 13. Ограничения платформы

- Web Speech API отдаёт только текст, аудиофайла нет. Поэтому при ошибках и обрыве сохраняется то, что успело распознаться, а не запись.
- Поддержка: Chrome и Safari. Firefox не поддерживает. В Chrome аудио уходит на серверы Google: это нужно отразить в политике конфиденциальности продукта и решить, нужно ли сказать об этом пользователю на экране доступа.
- Нужен HTTPS (localhost допустим), иначе микрофон недоступен.
- На iOS Safari запрос разрешения даёт только `getUserMedia` после действия пользователя; статус через `permissions.query` недоступен, поэтому показывается экран S1.
- Поведение при уходе в фон зависит от браузера: прототип реагирует на `visibilitychange`.
- Длинные непрерывные записи в мобильных браузерах могут обрываться системой раньше лимита; это покрыто E-recognition.

## 14. Точки расширения

| Что | Где | Как |
|---|---|---|
| Генерация моделью | `generator.js`, функция `window.generateVacancy(answers)` | Заменить тело на вызов серверной прослойки, сохранив результат `{ sections: [{ heading, items? , text? }] }`. Ошибка = отклонённый промис, интерфейс покажет S2-error. Ключ API на клиенте не хранить. |
| Правка транскрипта | Модель данных, раздел 5 | Добавить режим редактирования в Q-review, пишущий в `text`. `raw` не трогать. |
| Другой движок распознавания | `createRecognizer()` в `app.js` | Вернуть объект с `start/stop/abort` и колбэками `onresult(текстСессии)`, `onerror('no-speech'|'denied'|'other')`, `onend()`. |
| Подмена распознавания для демо и тестов | `window.__fakeRecognizerFactory` | Если задана, используется вместо браузерной. |

## 17. Проверено и не проверено

Проверено автоматическим прогоном в jsdom (64 проверки, включая «Назад»): текстовый путь, голосовой путь с подменой распознавания, тишина, короткий ответ, перезапись, закрытие и возврат, обрыв при уходе в фон, генерация, копирование, правка с итога, запись и чтение черновика.

Анимацию заливки проверил по кадру в Chromium (середина заливки видна), но саму плавность и поведение при включённом `prefers-reduced-motion` вживую не смотрел.

Не проверено: работа в реальных Chrome и Safari с живым микрофоном, вёрстка на реальных устройствах, поведение системного запроса разрешений, контраст измерителем, работа скринридера.
